How to Receive Tokens Across Networks With Different Decimals

To receive tokens across networks with different decimals, verify the destination token and network, then let the wallet or bridge convert units for the amount sent.

The Crypto Front Page DeskOct 23, 2026 · 20:41 UTC4 min read

To receive tokens on a network with different decimals, use the destination token’s details and let the wallet or bridge express the amount in that token’s smallest units. Decimals set how a balance is counted and displayed; they do not change the token’s market value. The key is to verify which token contract will receive the transfer and how the route converts between its units and the source token’s units.

What do token decimals change?

A token balance is stored as an integer in its smallest unit. The decimals setting tells software how many places to move the decimal point when showing that integer as a human-readable amount. For example, a token with six decimals represents one whole token as 1,000,000 base units; with 18 decimals, one token is 1,000,000,000,000,000,000 base units.

Think of decimals as the scale printed on a measuring cup: the same quantity can be written using finer or coarser marks. A token with more decimals can represent smaller fractions, but that alone does not make it worth more or mean there are more whole tokens. On Ethereum, the ERC-20 standard makes the decimals method optional, so software may need trusted token metadata to format a balance correctly.

When you enter “2.5” in a wallet, the wallet uses the destination token’s decimals to turn that readable amount into an integer for the transaction. A receiving wallet then uses those same destination details to turn the integer balance back into a readable amount. The recipient does not need to multiply or divide the amount manually.

How does a transfer handle different decimals?

A direct transfer on one network uses the decimals of the token contract on that network. A cross-network transfer adds a route that must map the source token to a destination token and account for how each represents its smallest units. The source amount, destination amount, any fee, and any unrepresentable remainder depend on that route’s rules.

For a bridge route, the transfer model matters alongside the decimal conversion. The fuller guide to portal bridge explains how to choose a transfer type for an integration. As a recipient, you mainly need to know which destination token the route delivers and whether the amount shown is before or after fees.

Before sharing an address or starting a transfer, check these details:

  • Select the destination network in the wallet or service that will receive the tokens.
  • Confirm the destination token’s contract address or other network-specific identifier; a matching name or ticker alone may not identify the same asset.
  • Review the displayed destination amount and fees, especially if the destination token has fewer decimals and cannot express every fraction of the source amount.
  • Use the route’s stated handling for rounding, dust, or minimum amounts. Different routes may reject a transfer or handle a small remainder differently.

What should you check after sending?

First, confirm that the transaction completed on the source network. A bridge transfer may then require separate processing before the destination network records the tokens, so a source transaction receipt by itself does not prove the destination balance has arrived. Follow the route’s status information and check the receiving address on the destination network.

If the transfer is complete but the wallet shows no token balance, check whether it is displaying the correct network and token contract. Some wallets do not automatically list every token; adding the verified destination token may make an existing balance visible. Compare the destination balance with the route’s final amount, allowing for stated fees and any conversion rules.

The practical rule is simple: decimals belong to a particular token representation on a particular network. The sender or bridge handles the unit conversion, while the recipient verifies the destination network, token, and final amount. For the next transfer, check those details before sharing the address, then watch for completion on the destination network.
