Why bridged tokens hide behind the wrong network

Tokens not showing in your wallet after bridging to layer 2? Switch networks, check the L2 explorer, and import the token using its destination contract.

The Crypto Front Page DeskNov 27, 2026 · 22:08 UTC5 min read

Switch your wallet to the destination L2 first; tokens not showing after a bridge usually means the wallet is on the wrong network or the L2 token needs importing, because it has its own contract address.

A bridge moves supported assets from a contract on one chain to a corresponding token contract on another. Your wallet account address may be the same on both networks, but the ERC-20 balance belongs to the network where the token contract exists. That is why an Ethereum balance can appear empty when you view the account on an L2, and an L2 balance can be missing from the wallet’s default token list.

Find the balance, then make it visible

Start with the transaction receipt or bridge status and identify the destination wallet address and network. Open that address on the L2’s block explorer, such as Basescan for Base. Look at its token balances and recent transactions. A completed deposit should appear there under the destination token contract; the explorer shows whether the funds arrived even when the wallet does not display them.

If the explorer shows the balance, switch the wallet to that L2. The wallet may still be showing Ethereum, where the bridged balance does not exist. MetaMask’s instructions for adding a network explain how to enable a network that is missing from its list.

Still no token in the wallet? Import it using the contract address shown on the L2 explorer. The Ethereum contract address points to the token on Ethereum; pasting it into the L2 import screen can show nothing or bring up a different token. Copy the destination contract from the explorer’s token page, then compare the address and balance with the explorer before importing. Treat a familiar name or ticker as a label, not proof that two tokens share a contract.

A bridge transfer can also be pending. Its source-chain transaction may have succeeded while the bridge is still processing the destination step. Follow the bridge’s transaction status, then look up the recipient address on the destination explorer. If the destination transaction has not completed, wait for the bridge’s stated process to finish and check again; if it has completed, use the resulting L2 token contract.

Bridging moves supported assets between Ethereum and Base through services such as Base bridge. On Base, USDC bridged through the native bridge became USDbC, a separate token from Circle-issued native USDC. Circle’s announcement of native USDC on Base distinguishes the two versions and lists their separate contract addresses. If the explorer shows USDbC, importing the native USDC contract will not reveal that balance; import the USDbC contract instead.

There is another possible case with a smart wallet. A smart wallet address can exist on an L2 before its wallet contract has been deployed there. Funds sent to that address may remain inaccessible until the wallet is deployed on that network. The explorer can show the destination balance, but the wallet’s deployment or recovery steps depend on the smart-wallet provider.

When the explorer shows no destination balance, recheck the recipient address, destination network, and bridge status against the original transaction. If those details do not explain the result, use the bridge provider’s support process and include the transaction hash and destination address.

  • Switch to the destination L2.
  • Look up the recipient address on its explorer.
  • Use the L2 contract address to import the token.
  • Confirm whether the transfer is pending, arrived as another token, or needs smart-wallet deployment.

Related

How do you add the Base network to MetaMask?

Use MetaMask’s network controls to add Base, then select it before checking the balance. Confirm the network details against an official Base source before adding a custom network.

How do you find a token’s contract address on Base?

Search your wallet address on Basescan and open the token listed in its balance or transaction. Copy the token contract address from that BaseScan token page, then compare it with the address you import in MetaMask.

Other recovery questions

Can tokens sent to an exchange on an unsupported L2 be recovered?

Possibly, but recovery depends on whether the exchange controls the receiving address and supports that network and token. Contact the exchange with the transaction hash, network, token contract, and receiving address; do not send more funds until it confirms the recovery path.

How do you swap USDbC to native USDC on Base?

Use a swap service that supports both contracts on Base, and confirm that the input is USDbC and the output is Circle-issued USDC before approving. The wallet balance changes from USDbC to native USDC; the underlying assets remain separate tokens with separate contract addresses.

Do bridged tokens appear automatically in Coinbase Wallet?

Some supported tokens may appear automatically, while others require adding or importing the asset. Select the destination network and check the wallet address on its explorer; if the balance is there but absent from the app, use Coinbase Wallet’s token-display steps for that network.
